# 思考、工具与流式更新修复

## 修复范围

- 思考计时在对应 `content.completed(kind: reasoning)` 结束，仍有 reasoning preview 时继续计时；模型重试后忽略旧尝试的完成边界。执行组保留独立的任务计时。
- 同一消息分段、同一模型步骤内，思考显示在所属工具之前。只调整 UI 展示，不修改持久事件、用户追加边界或工具执行顺序。
- 本地停止立即冻结展示，未完成工具使用终态图标和“已中断”标题。服务端取消仍按目标 turn 异步结算；显示状态不冒充持久生命周期事件。
- 高频 `content.delta`、`call.input` 和 `call.progress` 合并发布 UI 快照，窗口为 32 ms；生命周期事件立即发布。每条原始事件、增量文本、源坐标、恢复游标和同步 `onEvent` 回调均保留。
- 思考标题清理 Markdown 格式标记，标题与时长分开排版。独立思考摘要保持段落边界，正文仍展示上游提供的完整摘要文本。

## 实现边界

Eve 0.85.0 的两处修复保存在 `patches/eve+0.85.0.patch`，随 `postinstall` 应用：

1. `client/session-store.js`：进度事件延迟通知，结构事件立即刷新并清除待发布定时器；事件数组仅在已发布后再次写入时复制，保证旧快照不可变。关闭流时清除定时器。
2. `harness/emission.js`：收到 `reasoning-end` 或开始工具输入、工具调用时提交已有思考内容，避免将不同摘要粘在一起或把工具前的思考拖到调用之后才落库。

前端从同一不可变事件数组生成消息和展示视图，复用 `presentationSnapshot` 缓存。进度事件不再在 `handleEvent` 内逐条全量重放；React 更新合并发生在消息投影之前。

不直接使用 Eve 的本地 `agent.messages` 替代原始事件投影：该投影还包含提交回执及本地消息身份，与宿主现有的乐观消息、追加分段叠加会产生重复用户消息。快速追加和批量追加的浏览器回归覆盖这一边界。

增量合并仍分为两层：Eve 的 ordered emitter 合并积压的相邻增量；前端按完整 v27 事件累加内容并合并 UI 通知。没有恢复旧版本针对累计快照的删减逻辑，也没有丢弃原始 delta。

## 空思考占位的退出边界

没有可展示思考内容时，“正在思考”只表示当前模型步骤尚无可见输出。一旦该步骤出现正文或工具卡片（包含 `call.input` 参数预览），占位立即退出，并关闭它的界面计时器；空白 reasoning preview 也遵循同一规则。已有真实思考正文仍保留，执行组独立计时。

占位创建和空 reasoning 展示共用 `hasModelStepOutput`，直接查询官方消息投影中的 turnId、stepIndex 与可见 parts，不增加持久状态或修改工具事件。旧步骤的后台工具不会隐藏新步骤的占位，尚未取得 turnId 的乐观消息不会借用历史输出。浏览器回归覆盖无思考事件、空白 preview、空 completed、工具执行期间、后续步骤、重试与正文输出。

## 独立模式追加消息的认证身份（2026-11-14）

会话 `thread-1794564699778-lwv52j130zl` 的追加消息在 10:14:37 被接纳，却直到 10:22:56 原 turn 结束后才被下一 turn 消费。中间存在多次模型和工具边界，因此不能用“等待单个工具安全结束”解释。该会话的 21,173 条 `call.input` 也不能解释服务端已经记录的消费顺序。

直接请求通过 `standalone-cookie` 认证；独立模式 mailbox 路由却没有传入经过验证的 `callerAuth`，签名派发后使用了 `agent-mailbox-dispatch` 身份。Eve 比较 authenticator、issuer、principalType 和 principalId，只允许当前 turn 的同一调用方 steer；仅 principalId 相同不足以通过比较，消息因而等待下一轮。Host 路由已有身份传递。

修复将独立模式会话认证提取为共用函数，直接请求与 mailbox 均从已验证的浏览器身份构造相同的认证上下文。继续使用现有的持久化、签名派发、权限检查和 Eve steering；不增加队列或修改 Eve 的身份比较。浏览器提交的 `callerAuth` 不参与认证。

追加消息仍在 Eve 的安全边界应用：正式输出开始前的待定模型生成可以被中断；已开始输出后，在下一个提交边界应用追加内容。正在执行的普通工具安全结算并保留结果，再将追加内容交给后续模型调用；并非等待整个任务结束。`202 Accepted` 表示消息已接纳，实际消费以 `delivery.consumed` 为准。

新增回归贯穿独立 cookie 认证、HTTP 入队、JSON 持久化、签名派发及 Eve 真实的 `SessionInputQueue`。验证同一调用方能在当前 turn 消费、ask 回答保留 responder、浏览器伪造身份被忽略、不同浏览器仍被隔离；旧 authenticator 可稳定复现排入下一轮。相关单元测试 47 项全部通过，Next 生产构建、类型检查与 embed CSP 检查通过。
